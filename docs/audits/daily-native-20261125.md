# Daily: сверка оригиналов с 0.4.48 (25.11.2026)

База игры: [4d205b2](https://github.com/DanilaH/hue-gradients/tree/4d205b238ec9e04c9cf7a4fe33c04a6f4b9a52a8), поверх исследовательского PR #22. [Закрытые исходные доказательства, адреса и воспроизводимая модель](https://github.com/DanilaH/mini-games-kit/blob/6a5dca9832e62760b7cec370881f59438163796b/research/games/hue/porting/DAILY_SELECTION_2026-11-25.md), [PR геймкита #146](https://github.com/DanilaH/mini-games-kit/pull/146). Три оригинальных APK повторно сверены по SHA-256. Из Hue Too 2.1.1 (1013) проверены 10 окон ARM64, модель дала 104/104 совпадений с историческими native-фактов и проверила весь банк из 1950 уровней. Это не новый запуск APK на телефоне. Текущий код игры прочитан; новые потребительские тесты не запускались, реализации здесь нет.

## Сверка и передача

| ID / состояние | Исходное поведение | Что имеется / сценарий приёмки |
|---|---|---|
| h2-daily-open MISSING | Daily после 40 XP | У нас 2 задания уже с чистого профиля. Перенос 40/60 отодвинет режим до 2/3 кампании, после открытия четвёртой главы (30 побед). Не менять без решения владельца; предложен ранний доступ, Past появляется при первом рекорде. |
| h2-daily-date MATCH для локального дня | Новая сессия по локальной дате, при откате не перевыдаёт день | Дата локальная, сохранения привязаны к дню и типу. Проверить полночь, обратную дату, часовой пояс, возобновление старой партии. Общий UTC-календарь отдельно. |
| h2-daily-past PARTIAL | Завершённые, приоритет непревзойдённого perfect и ещё не назначенных; разрешён max(best,perfect) | Наше правило best−1 или повтор минимума. Предложение: сохранить явную цель улучшения как осознанную адаптацию либо согласовать мягкий лимит. Тесты для best 20/min 15, best=min и разрешённого последнего хода, старый контракт не меняется. |
| h2-daily-present PARTIAL | Текущий кластер с ≥5 завершениями, предпочитает невиданные и завершённые; perfect×3 секунд, ×6 boss | У нас приоритет доступного финала, затем поля активной главы/доступные; запас 10 сек и подвижные плитки, минимум 15 сек. На наших уровнях формула 001: 15 вместо 3, 006: 34 вместо 21, 015: 74 вместо 57, 060: 94 вместо 75. Это модель переноса формулы, не измерение времени человека. Сохранить запас до плейтеста. |
| h2-daily-future PARTIAL | C = последний кластер с ≥5 завершениями; предпочитает C+2, допускает повтор завершённого | У нас первая закрытая глава, только непройденные; тест 60/60 прямо требует исчезновения Future. Исправление P1: всегда доступный третий слот после завершения кампании, если достаточно разных полей. Кандидаты из ближайшей доступной/следующей главы с учётом реального прогресса, в конце — сложные завершённые поля. Не переносить +2 буквально на четыре главы. |
| h2-daily-history PARTIAL | Глобальная история снижает вес Past/Present, Future не учитывает её; три выбора независимы, совпадение ID возможно | Наше различие полей в рамках дня и least-recently-used по типу сохранить. Проверить ротацию на 30 дней, дубли, истощение пула, два разных профиля, сохранение выданного задания при смене версии. |
| h2-daily-reward MISSING | +1 XP за успешный слот | Есть earned-флаг, но XP кампании = число завершённых полей. Вариант: отдельный XP/счётчик мастерства или общий XP без подмены кампанийных завершений. Решение владельца. Приёмка: одна награда на (дата, тип) даже после перезапуска/повтора; не открывать главы без соответствующих кампанийных побед. |
| h2-daily-share UNKNOWN | Полный маршрут тройки не проверен на телефоне | Не менять одиночный экспорт выбранной работы. Проверить исходный экран полного завершения, кнопку, share sheet, итоговый файл. |

## Календарь и банк
В I Love Hue 1.3.1 (176) ежедневный подарок — 15 попыток, не поле; энергию не переносим. В Color Puzzle 6.13.0 (142) 10 фиксированных challenges и 10-минутный score mode, дата для квоты отправок. В этих версиях не обнаружен общий календарь задач; общий календарь Полусна — самостоятельное обязательство, не копия. [PR #22](https://github.com/DanilaH/hue-gradients/pull/22) уже фиксирует десять повторяющихся layouts на 30 полей и отсутствующий endpoint. Не снимать этот режим; источник публикации и trusted time остаются отдельным блокером, не начинать сервер/аккаунты без решения.

## Предлагаемый следующий пакет D2
Не меняя формулы таймера, порогов или экономики без согласования: исправить исчезновение Future на 60/60, учесть прогресс игрока при выборе главы (не текущую выделенную плитку), не допускать совпадения трёх полей и сохранять контракт уже выданной даты. Сценарии: 0, 1, 5, 10, 30, 59, 60 завершений; после первого рекорда три слота при наличии кандидатов; на 60/60 три слота 30 последовательных дат, минимум 2 разных Future за неделю при достаточном пуле, без дубликатов в один день. Одна победа/пауза/перезапуск на каждом типе. Существующее сохранение из 0.4.48 не теряет незавершённые попытки или награды. Прогон unit, Chromium, APK/телефон отдельно. Критерии предложения, не решение владельца.
