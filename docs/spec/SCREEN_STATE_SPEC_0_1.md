## 1. Общий принцип

Главное действие — собирать поле. Навигация не изменяет его RGB, помощь доступна без лимита энергии, возвращение не наказывает за пропуск. Открытия и награды объясняют следующий шаг, но не требуют серии обязательных окон.

Один устойчивый путь назад восстанавливает экран-источник и позицию списка. Системный Back сначала закрывает локальный слой (выбор цвета, помощь, подтверждение), затем возвращает экран. Из игры сначала сохраняется партия. На главной Back следует платформенному поведению, а не сбрасывает прогресс.

Приоритет главного CTA: последняя активная сохранённая попытка → ближайшая доступная незавершённая задача кампании → выбор главы/повтора. Другие незаконченные попытки доступны в своих разделах, запуск новой не уничтожает старую. Для одной и той же revision два расходящихся состояния требуют выбора, не смешивания клеток.

## 3. Ежедневная задача и время

Дата в названии — дата **UTC-слота**, с подписью «Обновление в 00:00 UTC» и пересчитанным локальным временем. Например, при Asia/Yekaterinburg это 05:00; приложение получает текущую зону устройства и не зашивает это значение для всех. Архивный день определяется slotId, а не местным временем доставки.

Переход суток не выталкивает игрока из текущей партии. После завершения старого слота можно открыть новый. Нет счётчика «дней подряд», штрафа за паузу и скрытого требования решить именно сегодня для накопительной награды. Сеть нужна для получения ещё не загруженных задач; архивные и текущие кешированные snapshot доступны без неё.

Если время сервера нельзя подтвердить, показывается последний полученный опубликованный каталог. UI не обещает, что загрузил сегодняшнюю задачу по одному системному времени. Подробные TTL, trust и API задаются в техническом пакете.

## 4. Игра: геометрия и обратная связь

По [уточнению владельца 0.2](VISUAL_DIRECTION_0_2.md) поле заполняет usable viewport между компактными HUD и фактическим banner slot. Прежние квадратная клетка48–72px, боковые поля16px и отдельный большой заголовок больше не являются требованиями.

Контроль: 320×568, 360×800, 412×915 CSS px, safe areas,150% UI-текст. Ширина и высота клетки независимы и обе не меньше48 CSS px; controls не меньше48×48 CSS px. Native dp/sp проверяются отдельно.

boardW=viewportW−safeLeft−safeRight; boardH=viewportH−safeTop−safeBottom−topHUD−bottomHUD−actualBannerHeight. Начальные HUD по48px. Число ходов/название не меняет размеры поля при обновлении: цифры имеют устойчивое место; длинное полное название доступно в контексте/меню. При text150% HUD измеряется заново.

Пример360×800, insets top/bottom по24, HUD по48: поле360×656,82% экрана. Баннер50 уменьшает высоту поля до606,75,75%;50px — только пример. При320×568 те же параметры дают320×374 с баннером, для6×5 клетки53,3×74,8. Это расчётный бюджет, не исполненный UI. Прямоугольники рендера и hit regions совпадают; округление не создаёт щели. При side-insets или увеличенном HUD бюджет пересчитывается; если сторона<48, требуется reflow.

На победе после записи собранное поле остаётся цветовой поверхностью сцены. Допустимы растворение границ/мягкость как переход к атмосферному представлению результата; обязательные результат/открытия/продолжение сохраняются. Ready CTA не ждёт декоративного эффекта. Точный исходный рисунок доступен в альбоме/экспорте. Карточка-концепт не определяет геометрию PNG.

Для короткого/горизонтального viewport нужна самостоятельная компоновка с боковыми actions, если верхний/нижний HUD съедают нужную высоту. Не переносить портретный процент заполнения в универсальное обещание для всех aspect ratios. Поле не scroll-контейнер; альбомы/списки прокручиваются обычным образом.

Pin имеет двухцветный знак, выбор — геометрический контур; оттенок плитки остаётся исходным. Drag не подменяет hit-test визуальным положением анимации. Tap–tap остаётся полноценным способом решения. Cancel/background не делает обмен и не увеличивает счётчик.

Сначала надёжная запись изменения/победы, затем подтверждённый результат. При записи, которая реально не завершилась, ввод не выпускает конфликтующий второй commit. Декоративные settle/win эффекты к этой блокировке не относятся. Reduced motion сразу показывает конечное состояние; звук/вибрация не являются единственным признаком действия.

## 5. Ошибки и конфликт: тексты и действия

| Ситуация | Сообщение / действия | Что сохраняется |
| --- | --- | --- |
| Локальная запись не подтверждена | «Не удалось сохранить. Повторить»; вернуть подтверждённое состояние или повторить операцию по её ID | Нельзя выдать новую награду второй раз из старого снимка |
| Локально сохранено, сеть отсутствует | «Сохранено на устройстве. Синхронизация позже» в профиле; игра продолжается | Попытка, завершения, очередь cloud |
| Два продолжения одной партии | «На устройствах разные продолжения»; превью, ходы, источник; «Продолжить это» | Обе ветки до выбора и recoverable копия; не считать больше ходов автоматически более новой версией |
| Две правки работы | «Есть две версии работы»; открыть/сравнить/выбрать текущую | Обе revision, никакого слияния цветов по времени часов |
| Guest → аккаунт | Показать итог объединения: задачи, работы, конфликтующие продолжения | Объединение уникальных фактов; не замена богатого профиля пустым гостем |
| Другая progressEpoch | «Профиль был сброшен на другом устройстве»; перейти к актуальному профилю, отдельно предложить сохранить местные работы | Старые события не воскресают в новом прогрессе |
| Запрос reset/delete без сети | «Для подтверждения операции нужна сеть»; доступен выход без изменения | Нельзя показывать удалённое облако, если сервер не ответил |
| Повреждённый snapshot | «Не удалось открыть задачу»; повторная загрузка / вернуться | Не считать задачу решённой и не запускать потенциально невалидную перестановку |
| Share отменён пользователем | Вернуться в preview без ошибки | Карточка и право на макет остаются |
| Изображение не записано ОС | «Не удалось сохранить изображение»; повтор / системное share | Победа и разблокированные форматы не откатываются |

Точные тексты auth/delete зависят от выбранной платформы и провайдера. Эта таблица не заменяет технический контракт удаления аккаунта.

## 6. Шесть макетов экспорта и базовый рендер

Начальные точные размеры выбраны для прототипирования. Экспорт содержит **собственные собранные поля**, без pins, выбора, ходов и полупрозрачного затемнения. RGB не проходят декоративный фильтр. Каждая плитка рисуется целочисленным прямоугольником; белые/тёмные зазоры между плитками не добавляются.

Fit означает вписать целое поле с квадратными клетками в заданную область: целая сторона клетки floor(min(regionWidth/width, regionHeight/height)), центрирование остатка. Форма не растягивается и не обрезается. Цвета окружающего поля/типографика ждут художественного профиля; геометрия ниже не зависит от выбора темы.

| ID / условие | Холст px | Геометрия и содержимое |
| --- | --- | --- |
| clean · первая победа | width×s, height×s, s=floor(1800/max(width,height)) | Только одно поле, длинная сторона до 1800, без текста и полей |
| export-caption · campaign 5 | 1800×2000 | Одно поле в (96,96,1608,1608); подпись в (96,1752,1608,152), до 80 code points, до двух строк |
| export-strip · campaign 15 | 2400×960 | Три разные выбранные работы: квадратные области 672×672 при x=96/864/1632, y=144 |
| export-grid · campaign 30 | 2000×2000 | Четыре разные работы: 856×856 при x/y=96 или 1048 |
| export-frame · daily 3 | 2000×2000 | Одно поле в (200,200,1600,1600); вокруг декоративное поле, не поверх плиток |
| export-diptych · daily 7 | 2400×1400 | Две разные работы: 1056×1056 при x=96/1248, y=172 |
| export-postcard · daily 14 | 1800×2200 | Поле в (96,96,1608,1608); личная подпись в (96,1792,1608,312), до 140 code points, до четырёх строк |

Подписи рендерятся как plain text выбранным шрифтом. До готовности шрифта длина символов не гарантирует вмещение; renderer измеряет строки. Нельзя автоматически обрезать пользовательский текст: показать «Сократите подпись» и сохранить её в форме. Нижняя граница размера шрифта задаётся с арт-профилем; экспорт не уменьшает текст бесконечно ради вмещения.

Чистый рендер доступен с первой победы. Награда открывает макет, а не новую валюту. Для ленты/сетки/диптиха выбрать нужное число разных завершённых работ из любых своих разделов; одна работа не заполняет несколько мест. Если материалов не хватает, явно показать «Выберите ещё N работ». Разные revision одной работы не обходят это правило.

Полная страница главы 15/15 имеет отдельное системное представление: сетка 3×5 карточек с заголовком главы и экспортом. Это не седьмая награда после шести форматов. Рабочий холст 1800×3000, квадратные области 496×496 при x=108/652/1196 и y=208/752/1296/1840/2384; заголовок занимает верхнюю полосу до y=160. Это отдельный шаблон страницы, палитры задач не обязаны образовывать единую панораму.

Сборка PNG/sRGB и системное сохранение/share проверяются на выбранной платформе. Успешный вызов share sheet не доказывает публикацию изображения другим приложением. Экспорт не отправляется автоматически, по завершении игры share sheet не открывается.

## 7. Доступность и ощущение

Доступность навигации отделена от цветовой природы самой задачи. У controls есть имена, фокус и текстовое состояние; закрыто/выполнено/ошибка различаются формой и подписью. Чтение экрана не объявляется полноценным решением цветовой головоломки без отдельного режима. Номинальный Oklab и размер клеток этого не доказывают.

Проверить клавиатуру/фокус там, где платформа их поддерживает; закрытие диалога возвращает фокус инициатору. Игровые accessibility labels не должны случайно раскрывать solved tileId как готовый ответ. Увеличенный текст не меняет цвета или положение поля при росте счётчика. Тема приложения не перекрашивает puzzle.

Звук и haptics соответствуют фактическому обмену/победе; no-op и cancel молчат. Исходное 150 ms settle из ядра — стартовый параметр, не измеренная оптимальная длительность. Непрерывный motion, физический feel и качество аудио будут приняты в приложении на устройстве.

## 8. Приёмка после реализации

Все пункты ниже **ещё не исполнены в приложении**. Проверки чистого валидатора находятся отдельно и не засчитываются как UI QA.

1. Начиная с пустого профиля, пройти №1–5; №6–15 доступны, можно выбрать не следующий номер.
2. При 9/15 десятая победа с помощью открывает опубликованную следующую главу; первая карточка одна, perfect без помощи отсутствует.
3. После последней главы нет фиктивного next chapter; повтор доступен, обычная награда не дублируется.
4. При ошибке записи победа не выдаётся повторно после перезапуска; «Сохранено» не предшествует durable commit.
5. Во время drag вызвать background/cancel; нет обмена, лишнего хода или звука. Tap–tap и быстрый следующий ввод сохраняют правила ядра.
6. Открыть/закрыть помощь; поле и ходы неизменны, assist persist проверен после смерти процесса.
7. Daily пересекает полночь, локальная дата переведена вперёд, архивная задача решена после паузы: награда определяется прежним slotId, не часами.
8. Нет сети при новом daily / есть кеш / слот не опубликован: три различимых состояния и рабочий путь в архив.
9. Белый черновик сохраняется, но не запускается; зеркальная неоднозначность блокируется; предупреждение близких цветов объясняется.
10. Rename сохраняет авторское прохождение; другой старт снимает его для новой revision; старое остаётся в истории.
11. Две конфликтующие правки на двух устройствах не теряют ни одну работу. Guest merge не очищает аккаунт.
12. Проверить все шесть export-layout, чистый рендер и страницу главы: поля вписаны без фильтра и обрезки; подписи не выходят за пределы; cancel share не теряет права.
13. На трёх базовых размерах, с safe areas и 150% текстом нажать фактические Back/помощь/далее; поля не перекрываются; landscape/reflow проверены отдельно.
14. Reduced motion и звук off: конечный результат понятен, очереди старых церемоний после восстановления нет.
15. Цветовые предупреждения и управление проверить на физических целевых устройствах; затем провести качественный плейтест темпа и ценности альбома/редактора.
