## Что должен проверить прототип

Игрок восстанавливает плавное цветовое поле обменом двух плиток. Закреплённые плитки служат опорами. Главная проверка: понятен ли обмен без объяснений разработчика, можно ли уверенно различить наши цвета на телефоне и хочется ли продолжать после нескольких задач.

Промежуточная сборка для проверки ядра рассчитана на офлайн-работу, 15 фиксированных задач, drag и tap–tap, просмотр решения, сохранение каждого принятого хода и личный результат. Daily, редактор, облако и мета для удержания входят в первый релиз по уточнённому решению владельца от 18 ноября; для них требуется дополнить продуктовые и технические контракты. Энергия в текущем рабочем плане отсутствует. Проверка ядра может предшествовать их подключению, но завершение этих 15 задач не является готовностью всей игры. Число 15 задаёт размер проверочного пакета, а не предел релизной кампании.

Платформа потребителя ещё не выбрана. Реализация должна использовать его проверенный scaffold и точную закреплённую версию kit; этот документ не утверждает, что в kit есть готовый Android runtime. Политика игры и контент остаются в consumer. **KIT IMPACT: NONE** для общих API и runtime.

| Подтверждение перезапуска | «Начать задачу заново?» | Сброс текущей партии только по подтверждению; завершённость и личный рекорд сохраняются |
| Меню / настройки | «Заново», правила, звук эффектов, reduced motion; вибрация только если платформа поддерживает её | Back закрывает верхнее окно и возвращает к тому же полю. Обычный выход с сохранением не требует подтверждения |

На первом поле достаточно подсказки «Поменяй две плитки местами» и однократной демонстрации выделения. Не делать обмен за игрока. При первом нажатии закреплённой плитки показать короткое пояснение «Плитки с точкой остаются на месте». Последующие нажатия дают только локальный отклик. Обучение не закрывает поле длинным текстом.

Освоенные шаги хранятся отдельно от сцены: `onboardingVersion`, `firstSwapDone`, `pinExplained`. Первый флаг обмена записывается вместе с самим обменом. Возврат после фона/нового процесса и повтор уровня не запускают приветствие заново. Правила можно открыть вручную. Смена версии обучения не должна автоматически повторять все уже понятные шаги.

Просмотр решения управляется игроком, как наблюдавшееся закрытие окна решения в Color Puzzle. Это общий UX-приём; оформление окна не копируется. Показ увеличивает `assistsUsed` на 1, не меняет перестановку или ходы, не требует оплаты и не делает обмен. До раскрытия сохраняется факт помощи; pending/ошибка видны, повторный запрос не дублируется. Во время открытого preview повторное нажатие не добавляет новую помощь. Закрытие, Back и возврат из фона возвращают прежнее поле. Автоматического таймера 1,2 с нет.

## Контракт поля и ввода

- Позиции нумеруются построчно с нуля. ID плитки равен её позиции в решении. Победа наступает, когда все ID стоят на своих местах; цветовое сравнение с допуском для определения победы не используется.
- Две разные подвижные плитки можно обменять независимо от того, были ли они уже правильно расположены. Один принятый обмен — один ход. Нажатие, выбор, отмена, нажатие pin и отпуск вне поля не добавляют ход.
- Tap–tap: первый tap выбирает плитку; второй по другой подвижной — обмен. Повторный tap по выбранной или tap по пустому месту снимает выбор. Tap по pin даёт отклик и снимает выбор.
- Drag: захват только подвижной плитки. Перемещение дальше 8 CSS px считается drag; это начальная настройка для плейтеста. Отпуск над другой подвижной плиткой совершает обмен; над исходной, pin или вне поля — отмена. Отменённый drag снимает выбор. До достижения порога жест обрабатывается как tap.
- Цель drag вычисляется по последним координатам `pointerup` и неподвижной сетке текущей модели, даже если после последнего `pointermove` ещё не было render. Координаты летящего спрайта и старый hover не определяют результат. Последний `pointerup` может отличаться от последнего move; pin/пустое место в этой конечной точке отменяют обмен.
- Один активный pointer. Второй палец игнорируется до завершения первого. `pointercancel`, потеря захвата, уход в фон и смена экрана отменяют незавершённый жест без изменения модели.
- Открытие меню или помощи отменяет жест и снимает выбор. Закрывающий tap не проходит на лежащую под окном клетку; Back закрывает верхний слой, а следующий Back возвращает к выбору задачи с сохранённой партией.
- Просмотр решения и незавершённая надёжная запись временно запрещают новый обмен; их состояния должны быть видимыми, без молчаливой потери тапа. Декоративная посадка не блокирует новый допустимый ввод: при новом pointerdown завершить прежнюю посадку в канонические позиции, затем обработать новый выбор по актуальной модели. Hit-test идёт по неподвижным ячейкам, не по летящему спрайту. Очереди старых жестов нет. После отмены/перехода старый pointer не может совершить поздний обмен.
- Логический обмен, увеличение счётчика и сохранение образуют одну принятую операцию. Косметическая анимация следует за сохранением и не является источником истины. Начальная длительность 150 мс; reduced motion отключает перемещение, оставляя понятную смену состояния. Это проектные значения, не измерения референсов.

Press начинается при вводе, не после записи. Во время удержания плитка следует актуальному pointer; декоративное сглаживание не создаёт отставание. Выбранная плитка и допустимая цель отмечены контуром; этот признак не сообщает правильность цвета. Художественное поднятие/scale не меняет hitbox. Выделение не перекрашивает цветовую поверхность и не перекрывает нужные для сравнения соседние плитки.

Для первого прототипа достаточно двух коротких собственных звуковых событий: подтверждённый обмен и победа; музыка не требуется. Необязательная haptic соответствует тем же событиям и уважает системную настройку. Нет cue на каждом перемещении пальца, двойного звука на одну операцию или залпа после resume. Повторный tap по тому же источнику и другие no-op не проигрывают звук успешного обмена. После mute новые игровые сигналы не запускаются; возможный короткий хвост декодера не считается новой операцией. Отключение звука/вибрации и reduced motion сохраняют весь смысл визуального состояния. [Контракт событий и проверок](https://github.com/DanilaH/mini-games-kit/blob/812b926ebfc82c6b0e5f3c6506145de2331028a0/research/games/hue/2026-11-16-apk-audit/FEEL_UI_UX.md#контракт-ощущения-для-нашей-первой-версии).

## Размер и визуальная читаемость

**Коррекция владельца, 18 ноября — [fullscreen dreamy/PSX 0.2](VISUAL_DIRECTION_0_2.md):** проверить 320×568, 360×800 и 412×915 CSS px с safe areas. Поле занимает всю доступную ширину и высоту между компактными HUD и фактическим banner slot. Клетки могут быть прямоугольными: cellW=boardW/columns, cellH=boardH/rows; обе стороны не меньше48 CSS px. Прежние обязательные поля16px, квадратная форма и предел72px отменены для игрового рендера. Максимум текущего пакета — шесть столбцов/пять строк; данные уровней и решаемость не меняются. Рендер и hit testing используют одни границы. Zoom/scroll не добавляются; при нехватке48px требуется reflow. Числа — проектная web-геометрия, native dp/sp и телефон проверяются отдельно.

Поле — главный визуальный объект. Точка pin видна на светлой и тёмной плитке благодаря двухцветному контуру. Выбор обозначается контуром, а не только изменением оттенка. Компактные HUD-кнопки имеют понятный знак, доступное имя и область нажатия не меньше48×48px; текст не перекрывает клетки. Полные подписи доступны в контекстном меню/справке; иконка не отменяет семантику действия. При победе не закрывать собранное поле немедленным полноэкранным окном.

Здесь px означают CSS px макета; для native Android проверить фактические dp/sp и ориентир 48×48 dp для обычных controls. Пиксели картинки сами по себе это не доказывают. Проверить 150% UI-текст, локализованные подписи и счётчик 9→10 / 99→100: соседние действия не сдвигаются и не уходят за экран. Поле не затемняется и не меняет оттенки ради декоративного состояния. Панель победы располагается вне поля; критические «Вернуться», «Отмена» и «Дальше» проверяются до автоскролла теста.

Точные цвета находятся в JSON. SVG ниже — проверка данных, **не утверждённая художественная подача интерфейса**. Номинальные цветовые расстояния не подтверждают доступность для людей с нарушениями цветовосприятия; её нельзя обещать по этому пакету.

## Сохранение и завершение

Сохранять после каждого принятого обмена, использования помощи, перезапуска и перехода. Минимальное состояние: `schemaVersion`, `contentVersion`, `revision`, `levelId`, `tileAtPosition`, `moves`, `assistsUsed`, список завершённых ID и личные лучшие результаты; отдельно настройки и освоенные шаги обучения. Выбор плитки, pointer, положение анимации и открытый preview не сохраняются. Для рекорда хранить отдельно лучший результат без помощи и лучший с помощью; один не подменяет другой.

Storage-адаптер потребителя обязан записывать полное состояние атомарно: транзакция либо временная запись с атомарной заменой. Нельзя удалить старое сохранение, затем независимо вставлять новое. Следующий принятый ход ждёт подтверждения записи предыдущего. Ошибка записи оставляет прежнюю сохранённую модель и показывает «Не удалось сохранить ход — повторить»; ложного подтверждения сохранения нет.

Последний обмен сразу сохраняет и решённую перестановку, и завершённость, и рекорд. Победная анимация запускается после этого. При перезапуске решённая партия открывает экран результата. Начисление завершённости идемпотентно: повторный запуск или повторный callback не открывает два уровня. Переход на следующую задачу — отдельное сохранённое действие по «Дальше».

На загрузке проверить версию, ID, длину/биекцию перестановки, неподвижность pins и неотрицательные целые счётчики. Не загружать чужую версию контента по совпавшему порядковому номеру. При несовместимой/повреждённой текущей партии явно предложить её перезапуск; не обнулять весь прогресс молча. При последующих версиях потребуется явная миграция по стабильным ID.

Целевое поведение прототипа: после background, обычной смерти процесса и force-stop возвращается последний подтверждённый ход. Это более строгий контракт, чем наблюдавшееся поведение незавершённой партии Color Puzzle после force-stop.

## Проверка реализации и граница готовности

| Проверка | Критерий |
| --- | --- |
| Пакет и решатель | 15 законных решений, совпадение минимума; pins не сдвигаются, все ID сохраняются |
| Drag и tap–tap | Одна и та же пара даёт одинаковую модель и ровно +1 ход |
| Отмены | Повторный tap, pin, отпуск вне поля, pointercancel, второй палец и уход в фон не создают лишнего обмена; cancel на допустимой цели снимает selection и не запускает звук подтверждения |
| Ввод между кадрами | move → up до следующего render даёт тот же результат, что с render; up у pin после move над допустимой клеткой отменяет обмен; результат определяется конечным вводом |

| Lifecycle | Прервать после записи, во время анимации, после последнего хода и перед «Дальше»; восстановить последнюю подтверждённую модель |

## Воспроизвести собственный пакет

Из каталога отчёта, Python 3.12, только стандартная библиотека:

```bash
python tools/build_prototype_pack.py --out /tmp/hue-levels-0.1.json
python tools/validate_prototype_pack.py --pack /tmp/hue-levels-0.1.json \
  --out /tmp/hue-validation-0.1.json --preview /tmp/hue-first15.svg
```

Валидатор не импортирует генератор. Он независимо считает циклы, строит и проигрывает законное решение; при ≤5 подвижных плитках проверяет расстояние полным BFS. Ближайшие номинальные цвета — диагностическая метрика, не универсальный порог качества. Пакет должен воспроизводиться побайтно; SHA-256 записан в `validation-0.1.json`.
